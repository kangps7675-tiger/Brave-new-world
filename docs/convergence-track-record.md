# 컨버전스 트랙레코드 — 설계 노트

작성일: 2026-08-07
목적: **"이 조합이 켜진 건 최근 N번뿐이고, 그중 M번은 48시간 안에 유가가 X% 움직였다"** 를 말할 수 있게 되는 것.

이 문장이 곧 상품이다. 오늘은 쓸 수 없다. 데이터가 없기 때문이다. 이 문서는 **오늘부터 그 데이터를 쌓기 시작**하는 구조를 설명한다.

---

## 0. 왜 이게 유일한 해자인가

디스코드 피드백이 맞다 — 3D 지구본은 2주면 복제된다. 레이어·지형 타일도 마찬가지다.

**그런데 12개월치 일별 시계열은 복제하는 데 12개월이 걸린다.**

그리고 원천 API 대부분은 과거를 돌려주지 않는다. GDELT 스냅샷, 텔레그램 알림, 공습 경보 — 오늘 안 받으면 영원히 없다. **오늘 지워진 하루는 복구 불가능하다.**

## 2. 감지 알고리즘

### 왜 단일 임계값이 아니라 컨버전스인가

단일 소스는 오탐이 너무 많다. 특히 FIRMS 열이상은 **오탐의 43%가 산업·광산, 14%가 가스 플레어**다. 페르시아만은 세계 최대 플레어 지대라서, **호르무즈에서 FIRMS 단독 급증은 분쟁이 아니라 석유산업 가동률일 가능성이 높다.**

→ FIRMS 는 `requiresCorroboration: true`. 다른 채널이 하나도 안 켜지면 계수하지 않는다.

### 채널 (독립성 기준으로 4개)

| 채널 | 컬럼 | z 임계 | 절대 하한 | 보강 필요 |
|---|---|---|---|---|
| `gdelt` | `mentions`, `points` | 3.0 | 8 | — |
| `telegram` | `telegram_count` | 3.0 | 4 | — |
| `airraid` | `air_raid_score` | 2.5 | 1 | — |
| `firms` | `fire_count` | **4.0** | 25 | **✅** |

`mentions`와 `points`는 둘 다 GDELT라 **하나의 채널로 묶었다.** 같은 소스를 두 채널로 세면 컨버전스가 아니라 중복 계수다.

**발화 조건: 독립 채널 3개 이상 동시.**

### 통계

- **평균·표준편차 대신 median·MAD.** 분쟁 신호는 꼬리가 두꺼워서, 과거 대형 사건 하나가 평균을 끌어올리면 다음 사건을 못 잡는다.
- **베이스라인에서 최근 3일 제외** (`BASELINE_GAP_DAYS`). 사건이 서서히 고조되면 자기 자신이 베이스라인에 섞여 z 가 죽는다.
- **베이스라인 60일, 최소 표본 21일.** 부족하면 발화하지 않는다 — 운영 초기에 헛발화하지 않기 위한 안전장치.
- **절대값 하한.** 평시 0인 희소 채널에서 0→3 은 z 가 무한대지만 의미가 없다.

### 버전 관리 — 트랙레코드의 생명

`ALGO_VERSION` 이 이벤트 id 에 들어간다: `2026-08-01:hormuz:conv-v1`

**v1 발화와 v2 발화를 섞어서 적중률을 말하면 그건 사기다.** 알고리즘을 바꾸면 반드시 버전을 올리고, 같은 버전끼리만 비교한다.

그리고 `channels_json` 에 **판정이 아니라 입력**(value/median/mad/z/fired)을 저장한다. 덕분에 v2 를 만들면 **과거를 재채점**할 수 있다. 판정만 저장했다면 과거는 영영 v1 로 고정된다.

## 3. 시장 반응

### 출처: FRED (미 세인트루이스 연은)

미 정부 저작물로 **퍼블릭 도메인**. 상업적 재배포 제약이 없다. Yahoo Finance 는 ToS 문제가 있어 쓰지 않는다 (`docs/commercial-licensing.md` 참조).

추적: `DCOILWTICO`(WTI) · `DCOILBRENTEU`(브렌트) · `VIXCLS`(변동성) · `DTWEXBGS`(달러지수)

### 한계 — 정직하게

**FRED 는 일별 종가만 준다. 인트라데이가 없다.** 그래서 "발화 후 4시간" 지표는 만들 수 없고, **D+1 / D+2 / D+5** 로 시작한다. 초크포인트 교란이 유가·운임에 반영되는 시간대를 생각하면 일별로도 트랙레코드는 성립한다. 인트라데이는 매출이 생긴 뒤 유료 피드로 붙인다.

### pct_change 만으로는 부족하다

"3% 움직였다"는 그 자산이 평소 얼마나 움직이는지 모르면 의미가 없다. 그래서 `z_change` 를 함께 저장한다 — 직전 90거래일 일간 로그수익률 표준편차 대비, 지평 h일이므로 √h 스케일.

> "유가가 3% 올랐다" (약함)
> **"평소 일변동 0.8% 대비 3.7σ 움직였다"** (강함)

### 시장 데이터도 우리가 보관한다

`market_daily` 에 직접 적재한다. FRED 는 과거를 주지만 운임지수 등은 그렇지 않고, **상품이 될 시계열을 남의 API 에 의존시키지 않는다**는 원칙이다. FRED 는 초기 발표를 나중에 개정하므로 upsert.

## 4. 하트비트 — 최악의 사고 방지

시계열이 상품이면 최악은 "지도가 안 뜬다"가 아니라 **"6개월 동안 스냅샷이 안 쌓였는데 아무도 몰랐다"**이다. 후자는 복구 불가능하다.

`pipeline_heartbeat` 가 매일 한 행을 남기고, 다음 중 하나라도 걸리면 `healthy=0` + `console.error`:

- 어제 전장 신호 스냅샷 0건
- 최근 7일 시장 시계열 0건
- 직전 스냅샷과 간격 2일 초과

**운영 권고:** 이 값을 주 1회라도 눈으로 확인하는 습관. 나중에 알림으로 승격.

## 5. 검증 상태

`src/lib/convergence.test.ts` — **10/10 통과** (실제 모듈 대상)

- 평시 미발화
- 채널 2개는 미발화 (최소 3개)
- 독립 채널 3개 → 발화
- **FIRMS 단독 급증 미발화** (플레어 방어)
- FIRMS 는 보강될 때만 계수
- 희소 채널 잡음 차단 + 대조군
- 베이스라인 부족 시 미발화
- 과거 이상치가 있어도 median/MAD 로 발화 유지
- id 에 algo_version 포함
- 채널 평가 4개 산출

마이그레이션 SQL 도 인메모리 SQLite 로 검증 — 4테이블·5인덱스 생성, append-only 중복 무시, FRED 개정 upsert 동작 확인.

## 6. 배포 순서

```bash
# 1) 마이그레이션
wrangler d1 execute <DB> --file=drizzle/0022_signal_convergence.sql

# 2) FRED 키 (무료 발급: https://fredaccount.stlouisfed.org/apikeys)
wrangler secret put FRED_API_KEY

# 3) 배포 후 첫 실행 로그 확인
#    [convergence] fired=... 또는 [heartbeat] UNHEALTHY 확인
```

**주의:** 배포 직후에는 발화가 없는 게 정상이다. 베이스라인 최소 표본이 21일이므로 **약 3주간은 감지기가 침묵**한다. 그동안 데이터는 쌓인다.

## 7. 앞으로의 순서

| 시점 | 할 일 |
|---|---|
| **오늘** | 배포. 시계가 돌기 시작한다 |
| ~3주 | 베이스라인 충족. 첫 발화 관찰 시작 |
| 1~3개월 | 발화 로그를 눈으로 검토. 오탐 패턴 발견 시 → **v2 를 만들되 v1 기록은 남긴다** |
| 3~6개월 | `convergence_outcomes` 에 표본 축적. 첫 통계가 나오기 시작 |
| 6~12개월 | "N번 중 M번" 을 말할 수 있음. **이때 처음으로 판매 가능** |
| 그동안 | 미디어로 오디언스 축적 — 나중에 이걸 살 사람들 |

## 8. 법적 경계 (자본시장법)

2024년 8월 14일 시행 개정 자본시장법 기준:

- **양방향 유료** (질문 답변·채팅·개별 조언·리딩) → **투자자문업 등록** 대상. 무등록 시 불법
- **단방향** (뉴스레터·알림) → **유사투자자문업 신고** + 사전교육. 미신고 시 1천만원 이하 과태료

**설계에 반영된 것:** 스키마에 "추천" 컬럼을 만들지 않았다. 사실과 통계만 저장한다.

| 표현 | 판정 |
|---|---|
| "원유 매수하세요" | ❌ 투자조언 |
| "이 신호 뜨면 유가 오릅니다" | ❌ 예측 단언 |
| **"이 조합은 최근 2년간 4번 발화했고, 그중 3번은 D+2 유가가 +2σ 이상 움직였습니다"** | ✅ 사실 + 통계 |

세 번째가 법적으로 안전하고, 솔직히 **더 설득력 있다.**

커뮤니티·Q&A·오픈채팅을 붙이는 순간 양방향이 된다. 붙이기 전에 반드시 확인할 것.
