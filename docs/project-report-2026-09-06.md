## 0. 한 줄 정체성과 지금 상태

**"개인용 인텔리전스 터미널 — 전문가급 밀도의 지정학·지경학 OSINT를, 개인이 구독료 내고 쓸 수 있는 자리."**

이 문장은 최근 확정된 북극성(`docs/geopolitics-geoeconomics-structure-notes.md`, 2026-09)이고, 이 리포트 전체를 관통하는 기준선이다. 지금까지의 흐름을 요약하면:

1. **경쟁사 14곳 비교** 결과 "지구본 + 타격/드론/AIS + 코리도/축관계망/BRI·DFC"를 다 가진 곳은 없다 → 조합 자체는 자산.
2. 그런데 자체 감사 결과 **"넓지만 얕다"** — 레이어는 많은데 개별 레이어의 신선도·검증·실측 좌표가 약하다.
3. **"전세계를 다 실측해야 하나"** 질문 → 아니다. CRINK(중·러·이란·북한) 스코프 밖은 정밀 처리할 이유가 없다.
4. 이 질문 자체가 **"타깃이 안 정해졌다"**는 더 큰 문제의 증상이었다는 게 드러났고, 2026-09에 타깃이 좁혀졌다.
5. 남은 차별점은 **코리도·축관계망·지경학** 세 가지뿐이고, 이 셋이 지금 프로젝트에서 가장 얕은 부분이라는 게 최대 리스크로 진단돼 있다(`concept-swot-14-competitors.md`).

즉 지금은 "무엇을 더 만들까"보다 **"이미 있는 걸 어떻게 정리하고, 이미 정한 방향대로 완성할까"**가 급한 단계다. 이 리포트의 마지막 장(12장)이 그 정리다.

## 2. 타깃 사용자

### 2.1 확정된 타깃 (2026-09)

| 구분 | 내용 |
|---|---|
| **아니다** | B2B OSINT SaaS(기관 대상 팔란티어형 영업) |
| **맞다** | **개인** — 뉴스 과다 섭취자·지정학 관심층·해외 거주자·리서치 입문자·인디 저널리스트/크리에이터 |
| **핵심 Job** | "오늘 세계가 더 시끄러운가 → 어디서 → 왜" 를 GTS(긴장지수) + 지도 + 출처로 확인하는 것 |
| **참조 모델** | 블룸버그 터미널(연 ~2,900만원, 기관 전용)과 팔란티어(개인 SKU 없음) 사이의 빈 자리를, TradingView가 트레이딩 영역에서 이미 증명한 것처럼 안보·지정학 영역에서 채운다 |

이 프레임이 그동안 갈팡질팡하던 논쟁들을 실제로 정리해준다.

- **"레이어가 너무 많은 거 아닌가"** → 밀도는 버그가 아니라 컨셉이다. "애널리스트처럼 세상을 본다"는 서사가 있으면 많은 레이어 = 정체성이 된다.
- **"게임화 요소(GTS 상승/하락 맞히기, 벙커 감성투표)를 빼야 하나"** → 안 빼도 된다. 페이퍼 트레이딩·예측 게임은 블룸버그/TradingView 문화권에서 이미 자연스럽다. 다만 톤은 "전쟁 오락화"가 아니라 **"애널리스트도 자기 판단을 연습한다"**로 가야 한다 (2026-08-30 UX 감사에서 이미 톤 완화 작업 진행).
- **가격 모델** → 광고형 무료보다 TradingView Pro 같은 "커피값 프리미엄 개인 구독"이 이 프레임과 맞는다.
- **출처 투명성** → 장식이 아니라 필수 조건이다. "개인용 팔란티어"를 자처하면서 출처를 숨기면 포지셔닝 자체가 무너진다.

### 2.2 페르소나 예시 (Job-to-be-done 기준)

1. **뉴스 헤비 유저**: 하루 여러 매체를 훑는 대신, 90초 안에 "오늘 뭐가 심각한가"를 지도 하나로 확인하고 싶다.
2. **해외 거주/파견 한국인 또는 관련 업종 종사자**: 특정 지역(중동·대만해협 등)의 긴장도와 관련 자산(유가·운임)을 같이 보고 싶다.
3. **리서치 입문자/학생**: 출처가 명시된 1차 데이터를 지도 위에서 익히고 싶다 (교육적 사용).
4. **인디 저널리스트/크리에이터**: 스크린샷·공유 링크(`?scene=`)로 콘텐츠를 만들고 싶다.

### 2.3 타깃 결정이 아직 못 끝낸 것

`docs/ux-product-audit-2026-08-30.md`의 3번 항목(제품 정체성)은 "코드로 해결 불가"로 분류돼 있었고, 실시간 분쟁 지도·OSINT·GTS·경제 지표·해운·지정학 관계망·시장 정보·예측 게임이 한 서비스 안에 공존하는 게 사용자 스스로에게도 혼란스러웠다. 2026-09 구조 노트가 방향(개인용 인텔리전스 터미널)은 정했지만, **정보구조(IA) 재배치 자체는 아직 실행되지 않았다** — 이건 12장 로드맵의 1순위다.

## 3. 제품 구조 — 지정학 / 지경학 이원 모드

`ViewModeSwitcher` 하나로 레이어 패키지·상단 nav·하단 Intel·fetch 정책이 통째로 바뀐다. 이 축이 제품의 뼈대이며 "바꾸지 말 것" 원칙으로 문서에 명시돼 있다.

### 3.1 지정학 (Geopolitics)

- **초점**: 전선·분쟁·GDELT 뉴스·Telegram OSINT·공습 경보
- **상단 nav**: 반서방 4허브 고정 — **중국 · 러시아 · 북한 · 이란** (`grid-cols-4`)
- 허브별 드롭다운 5종: 국경·우군 관계망 / 우군 국가 / 영유권 주장 및 영향 / 무기거래(SIPRI) / 반서방국간 분쟁 외교사(11개 큐레이션 에피소드)
- **간판 지표**: GTS(Global Tension Score, 옛 GTI) + 제재 회피 강도(칩·회랑·위장선박)
- **히어로 기본 ON**: 전쟁구역·동아시아 ADIZ·GDELT 4종·군용기·AIS·물류/초크·축 관계망·해저 케이블

### 3.2 지경학 (Geoeconomics)

- **초점**: 증시·유가·물류·에너지·제재 RSS
- **nav**: 검색 포커스 시 6그룹(에너지·초크포인트 / 에너지 허브 / 금리·통화 / 금융·무역 / 공급망·제조 / 원자재·식량)
- **간판 지표**: GSCPI(공급망압력지수) · 해운 프록시 · PortWatch 정체 스트레스
- **히어로 기본 ON**: AIS·민항·물류/초크·크리티컬 노드·해저 케이블·유가스 파이프·원자력·AI DC·항구·공항
- **Job**: 초크/에너지/물류 충격을 지도에서 읽고 → 관련 선물·지수(티커·허브)로 이어주는 "개인용 시장 리스크 터미널" (매매 중개가 아니라 해석기)

### 3.3 두 모드를 가르는 실제 데이터 모델

CRINK 축 관계망의 관계유형(`AXIS_RELATION_COLORS`)이 이미 두 모드를 데이터 차원에서 나눠놓고 있다.

| 관계유형 | 소속 모드 |
|---|---|
| `arms`(무기이전) · `patronage`(후원) · `diplomatic`(외교) | 지정학 |
| `energy`(에너지) | 지경학 |
| `hybrid` | 렌즈별로 분리 반영(economy hybrid/energy = 지경학, conflict hybrid = 지정학) |

즉 "이코노미 모드"는 완전히 새로 만드는 기능이 아니라, 이미 있는 축 네트워크를 필터링해 완성하는 작업이라는 게 핵심이다.

### 3.4 콘텐츠 매핑 표 (구조 노트 원문)

| | 지정학 — 누가 누구와 싸우고 동맹하는가 | 지경학 — 막힘이 시세에 닿는가 |
|---|---|---|
| 간판 | GTS + 제재 회피 강도 | GSCPI · 해운 프록시 · PortWatch |
| 첫 화면 | 전선·NEPTUN·항모·기지·GDELT war | 초크·항로·항구·가스/LNG·무역 코리도·에너지/결제 축 |
| 수동 토글 | ADIZ·축 군/대리 hybrid 등 | BRI/DFC·송유관·민간 AIS·제재 명단·AI DC·핵심노드 |
| 넣지 않음 | BRI/DFC | 전선·군함·제재 회피 칩(지정학 전용) |
| 게임화 | GTS 감각 연습·벙커 | 없음 (해석·딥링크만) |

## 4. 데이터베이스 & 데이터 아키텍처

### 4.1 엔진과 계층

- **런타임 DB**: Cloudflare **D1** (SQLite 호환) — `wrangler.jsonc`에 바인딩 `DB`, database `conflict-view-db`
- **ORM**: Drizzle ORM 0.45 + drizzle-kit (마이그레이션 생성/적용)
- **적재 방식**: 별도 Cron Worker `conflict-view-ingest`(`workers/cron-ingest`)가 FIRMS·GDELT·뉴스·AIS·ADS-B 등을 주기적으로 가져와 D1에 씀. Next.js 앱 자체는 요청마다 외부 API를 직접 두드리지 않는다(장애 시 폴백만).
- **대용량 정적 자산**: R2 버킷 `conflict-view-data` (지도 타일, OSM PBF 파생물, 대용량 GeoJSON, 오디오 등)
- **2층 구조 원칙** (`docs/data-architecture-2tier.md`): "1층 = 클라우드 창고(R2+D1, 정적·스냅샷)", "2층 = 실시간 빨대(앱 API 폴링, 뉴스/Telegram/NEPTUN 등)". 유저 브라우저는 창고에서 읽고, 당장 변하는 것만 빨대로 천천히 가져온다.

### 4.3 주요 테이블 (`src/db/schema.ts`, 32개 테이블)

도메인별로 묶으면:

- **위성/사건 관측**: `firmsFires`(NASA FIRMS 화재), `gdeltPoints`(GDELT 이벤트)
- **우크라이나 전선**: `ukraineControlPaths`/`ukraineControlBuilds`(VIINA 렌더 전용), `disputeHatchPaths`/`disputeHatchBuilds`(분쟁 해치)
- **뉴스/영상/텔레그램**: `newsStreamSnapshots`/`newsStreamItems`, `videoNewsSnapshots`, `telegramAlerts`
- **선박/항공**: `aisVessels`, `adsbAircraft`, `submarineTunnels`, `shipMovementReports`/`shipMovementObservations`
- **경보/상황**: `sitrepEvents`, `ukmtoIncidents`, `navareaFeatures`, `militaryExercises`, `airRaidAlerts`, `referenceMonitorItems`
- **랭킹/게임화**: `dailyEntityRanks`, `dailyRankPredictions`, `dailyPrompts`, `dailyPredictionStats`, `bunkerSentimentVotes`
- **컨버전스 트랙레코드(신설)**: `theaterSignalDaily` 등 4테이블 — 전장 신호 일별 집계, 시장 반응(FRED), 파이프라인 하트비트
- **인프라**: `pushSubscriptions`, `uiEvents`, `livingTimelineEntries`, `briefingPeriodStats`, `ingestRuns`

**보존 정책이 최근 바뀐 부분**(4.4 킬러콘텐츠 참고): `theaterSignalDaily`는 원래 120일 삭제였다가 **삭제 중단**, `airRaidAlerts`는 7일→**1,200일**로 늘어났다. 트랙레코드 자산화를 위한 의도적 결정이다.

- **뉴스/OSINT**: `/api/gdelt`, `/api/news-stream`, `/api/video-news`, `/api/telegram-alerts`, `/api/news-digest`
- **경제/시장**: `/api/stock-tickers`, `/api/world-stats/*`(macro/market-lamp/rankings/compare/history), `/api/world-bank`, `/api/sovereign-rates`, `/api/freight-indices`, `/api/portwatch`
- **정적 레이어**: `/api/layers/*`(conflict-zones, arms-embargo-zones, ai-data-centers, economic-centers, sanctions-entities, ukraine-control, gta-interventions, strategic-missile 등)
- **게임화/개인화**: `/api/daily-ranks`, `/api/daily-predict`, `/api/bunker-sentiment`, `/api/ask-layers`
- **AI 보조**: `/api/claude/*`(news-insight, why-matters, user-analyze, status) — Anthropic SDK 직접 연동
- **렌더 전용(라이선스 방어)**: `/api/render/ukraine-control`, `/api/render/dispute-paths`, `/api/render/viina-session`

### 4.5 왜 이 구조인가

1. 무료·공개 API 대부분이 요청 시 직접 부르기엔 느리거나 rate-limit이 있어, cron 적재 + D1 캐시로 완충한다.
2. VIINA(우크라이나 전선) 같은 ODbL 데이터는 "렌더링 전용" 원칙을 지키기 위해 원본 좌표를 export하지 않는 API(`/api/render/*`)로만 노출한다 — 재배포 리스크 차단이 스키마 설계에 직접 반영된 사례다.
3. 게임화(랭킹·예측)와 트랙레코드(컨버전스) 테이블을 분리해, "판정"이 아니라 "입력값"(z-score, median, MAD 등)을 저장한다 — 알고리즘을 나중에 바꿔도 과거 데이터를 재채점할 수 있게 설계돼 있다.

## 6. 킬러 콘텐츠 — 경쟁사가 못 가진 것

경쟁사 14곳(Liveuamap, ISW, ACLED, GDELT, DeepStateMap, CFR, Defcon Level, armedconflicts.org, Recorded Future, Crisis24, MarineTraffic, AidData, OSIRIS, WarWatch) 비교 결과, **사건형 레이어(타격·드론·AIS 실시간 마킹)는 이미 업계 표준**이 됐다. 남는 차별점은 아래 세 가지뿐이고, 동시에 지금 가장 완성도가 낮은 부분이기도 하다 — 즉 "여기에 투자해야 살아남는다".

### 6.1 CRINK 축 관계망 (유일한 데이터 모델)

사건 단위 마킹이 아니라 **국가 간 관계 그 자체**(후원·무기·에너지·외교·하이브리드)를 구조화한 곳이 경쟁사 어디에도 없다. `AXIS_EDGES`(관계 그래프) + `AXIS_HUB_META`(허브별 고유색) + `AXIS_RELATION_COLORS`(관계유형별 색)로 구성되며, 최근(2026-08) 호버 인터랙션이 정교화됐다 — 기본은 국가/허브 색으로, 호버하면 관계유형 색(빨강=무기, 주황=하이브리드 등)으로 바뀌어 "이 선이 무슨 관계인지"를 설명한다. 공사 중 진행 경과(회차별 수정 이력)가 프로젝트 메모리에 상세히 남아 있다.

### 6.2 전략 코리도(물류·에너지 회랑) — 실측 지오메트리

TSR/TCR/TMGR/중국-키르기스스탄-우즈베키스탄 철도·중부회랑(Middle Corridor)·쟁게주르 회랑·중국-이란 철도·INSTC 등, 뉴스 그래픽에 나오는 회랑들을 직선 추정이 아니라 **실제 철도·도로 지오메트리에 스냅**시키는 작업이 진행 중이다. 레일↔해운↔레일처럼 운송수단이 바뀌는 다구간(multi-leg) 경로를 하나의 연결된 시스템으로 렌더링하고, 호버 시 길이 가중 반짝임(glint) 애니메이션이 재생된다.

- **현재 상태**: 벨라루스·우크라이나만 실측 OSM 스냅 완료, 러시아/아시아/쿠바/베네수엘라는 진행 중.
- **신뢰도 점수화**: `corridor-ranks.json` — OSM 매칭 수 + UN Comtrade 양자무역 + UNCTAD 항만처리량/해운무역 + 철도화물(현재 0, 접근 차단) + PortWatch(현재 0, 접근 차단)를 블렌딩한 신뢰도 스코어.
- **미착수**: 코리도 자체를 UI에서 독립 토글로 노출하는 기능(현재는 축 네트워크에 딸린 백그라운드 지오메트리로만 존재).

### 6.3 확전 신호(Escalation Signals) — 완전 자체 저작물

**"확전은 규모가 커지는 게 아니라 임계선을 넘는 것"**이라는 RAND 확전 이론(`A Vocabulary of Escalation`, `Dangerous Thresholds`)에 근거해, 도네츠크 대규모 포격(임계선 안 = 신호 아님)과 루마니아 영공 진입 드론 한 대(임계선 밖 = 신호)를 구분한다.

- 수평(영역 확대)·수직(강도/능력 확대) 두 축, 15종의 임계선(주권영역·핵시설·조약영토·사이버·해저인프라·핵신호 등)에 법적/이론적 근거를 각각 명시.
- 대서양 플랭크(13개국) vs 인도태평양 플랭크(8개국)를 **동일 규칙·동일 가중치**로 처리 — "유럽 확전만 위험하다"는 편향을 구조적으로 차단.
- 판정 근거를 전부 화면에 공개(`formatFactors()`) — "확전이다/전쟁 임박이다" 같은 단정은 절대 하지 않고, "공개 보도에 이 임계선 유형이 언급됐다"까지만 말한다.
- 노출량 조절 계층 분리 — 동일 사건 중복 접기, 동시 노출 기본 3건, 억제된 신호도 개수는 표시(과소 노출로 오독 방지).

### 6.4 컨버전스 트랙레코드 — "이 조합이 뜨면 시장이 움직인다"를 증명하는 인프라

**이게 유일한 진짜 해자(moat)라는 게 2026-08 설계 노트의 결론이다.** 3D 지구본과 레이어는 2주면 복제되지만, **12개월치 일별 시계열은 복제하는 데 실제로 12개월이 걸린다.** 원천 API 대부분이 과거 데이터를 주지 않기 때문에 오늘 안 쌓으면 영원히 없는 데이터다.

- 4개 독립 채널(GDELT·Telegram·공습경보·FIRMS) 중 **3개 이상 동시 발화**해야 "컨버전스 이벤트"로 잡는다. FIRMS(위성 열원)는 오탐률이 높아(43%가 산업/광산, 14%가 가스 플레어) 단독으로는 절대 계수하지 않는다.
- 평균/표준편차 대신 median/MAD 사용(꼬리가 두꺼운 분쟁 데이터에 맞춤), 베이스라인 60일 최소 21일 확보 전엔 발화 안 함.
- 시장 반응은 FRED(미 연은, 퍼블릭 도메인) WTI/브렌트/VIX/달러지수를 D+1/D+2/D+5로 추적, `pct_change`가 아니라 `z_change`(평소 변동성 대비 몇 시그마)로 저장.
- **버전 관리가 핵심**: 알고리즘 버전(`ALGO_VERSION`)이 이벤트 ID에 박히고, 판정이 아니라 원본 입력값을 저장해 나중에 과거를 재채점할 수 있다. "v1과 v2 적중률을 섞어 말하면 사기"라고 문서에 명시.
- **하트비트 모니터**: "지도가 안 뜬다"보다 "6개월간 스냅샷이 안 쌓였는데 아무도 몰랐다"가 더 큰 사고라는 인식하에, 파이프라인 정상 여부를 매일 자체 점검.
- **타임라인**: 배포 후 3주는 베이스라인 확보 기간이라 침묵, 3~6개월에 표본 축적, **6~12개월 후에야 "N번 중 M번 유가가 움직였다"를 팔 수 있는 상태**가 된다. 즉 이건 지금 당장의 킬러 콘텐츠가 아니라 **지금 시작해야 나중에 킬러 콘텐츠가 되는 자산**이다.
- **법적 설계**: 자본시장법상 무등록 투자자문업 리스크를 피하기 위해 스키마에 "추천" 컬럼 자체를 만들지 않았다. "이 조합은 최근 2년간 4번 발화, 3번은 D+2 유가가 +2σ 이상"까지만 말하고 "사세요"는 말하지 않는다.

### 6.5 EvidenceTier — 인식론 자체를 상품화

지도 위 정보를 "진실 점수"가 아니라 **"이게 어떤 종류의 앎인가"**로 6단계 구분(`observed`>기계 관측>실선 / `reported`>매체 교차확인>실선 / `claimed`>당사국 발표·독립검증 없음>점선 / `unverified`>한 경로 전언>점점선 / `model`>자체 계산>파선 / `synthetic`>데모>프로덕션 자동 제외). 매체 신뢰도(Tier 1~3)와는 별개 축이다. 이런 수준의 인식론적 투명성을 UI 렌더 스타일(실선/점선/파선)까지 연결한 경쟁 서비스는 없다 — 다만 이게 아직 **입구 화면에 노출되지 않고 코드/문서 안에만 있다**는 게 스스로 진단한 최대 손해다(SWOT C번 항목).

### 6.6 데이터 출처 카탈로그 자체의 정직함

`src/data/sourceCatalog.ts`(1,182줄, 50개 항목)는 라이선스가 안 풀린 것, 데이터가 가짜인 것까지 전부 있는 그대로 코드에 문서화돼 있다. 킬러 콘텐츠라기보다 킬러 콘텐츠의 "신뢰 기반"이며, 아직 이 카탈로그가 사용자에게 보이지 않는다는 것 자체가 기회다(8개 책갈피로 정리된 초안이 이미 `docs/data-source-parchment-content.md`에 있음, 8.3 참고).

### 7.2 레이어 적용 모델 — README와 실제 코드가 어긋나 있던 사례

README에는 "체크 → 즉시 지도 반영"이라고 적혀 있지만, 실제 코드는 draft 상태를 만들고 "적용하시겠습니까?" 확인을 거치는 모델이었다(2026-08 시점). 이 불일치 자체가 `DESIGN.md`를 만든 계기였다 — **"UX 결정이 코드에 도달하지 못하고 중간에서 멈춘 상태가 문서에는 완료로 기록돼 있었다"**. 결정된 방향(즉시 반영 + Undo 토스트)은 있지만 아직 통일 작업이 안 끝났다.

### 7.3 타이포그래피 체계

### 7.4 사운드 시스템

체크박스 ON이 즉시 재생을 의미하지 않고, 트리거 기반이다(공습 칩 클릭 시 사이렌, 레이어 ON+이벤트 진입 시 폭발음, 전선 위 교전음, 항모가 화면에 있을 때 갑판음 등). 티커·모드 전환·일반 클릭은 항상 무음. 전역 음소거 벨 버튼 상시 존재.

### 7.5 모바일 전략 — "지구본을 안 띄우는 게 정답"

폰은 3D 지구본을 아예 마운트하지 않는다(성능상 확정, 번복 안 함). 문제는 제품이 아니라 **성장 루프**였다 — 데스크톱에서 만든 `?scene=` 공유 링크를 폰에서 열면 지구본이 없어 장면을 못 보고, 재공유가 끊긴다. 그래서 폰에서의 약속을 "지도"가 아니라 **"오늘의 긴장을 읽고 공유된 장면을 이해할 수 있다"**로 재정의했다: `?scene=` → 카드 랜딩(지명·주제·GTS·CTA)은 완료, OG/정적 프리뷰 이미지는 미완, 조건부 MapLibre 2D 최소 뷰는 미착수.

welcome 단계 직후, 도메인 선택 전에 끼워 넣을 신규 게이트 콘텐츠 초안이 8개 책갈피(실시간 감시·추적 / 분쟁·타격·공중경보 / 인프라·에너지·자원 / 무역·경제 / 축·코리도 데이터 / 제재·분쟁지대 / 뉴스·OSINT·미디어 / 지도 렌더링 인프라)로 이미 작성돼 있다. 라이선스 미확정·가짜 데이터인 것도 숨기지 않고 그대로 적는다는 원칙이며, **아직 UI로 구현되지 않았다**.

## 10. 라이선싱 · 법적 현황

### 10.1 상업 이용 게이트(`verify:commercial`, 빌드에 자동 포함)

| 구분 | 개수 | 유료 노출 |
|---|---|---|
| `allowed` | 42 | 가능 |
| `license-required` | 13 | 계약 필요 |
| `prohibited` | 3 | 약관상 금지 |
| `unknown` | 6 | 확인 전까지 차단 |

**유료화를 지금 켜면 21개 레이어가 빌드를 막는다.** 명시적 금지 사례: adsb.fi/ACLED(둘 다 비상업 전용 조항, ACLED는 이미 제품에서 완전 제거됨). 계약하면 열리는 것(값어치순): GTA(CC BY 4.0이나 서비스 약관은 비상업) · MarineTraffic AIS · Statistics of the World API · 텔레그램 OSINT(현재도 절반 스니펫+CTA로 우회 운영 중) · UKMTO(비공식 엔드포인트, 정식 피드 요청 필요).

### 10.2 핵심 원칙

- "화면만 보여줘도 유료면 상업적 이용" — CC NonCommercial의 "or monetary compensation" 조항 근거로 이미 코드 주석에 박혀 있다.
- 재배포(원본 export 여부)와 상업성(유료 접근 여부)은 **다른 축**이며 각각 별도 게이트(`viinaRenderGate` vs `commercialGate`)로 분리돼 있다.
- 유료화의 진짜 근거는 "남의 데이터 접근권"이 아니라 "우리 판단"(확전 신호·GTS·마찰 에피소드·초크포인트 브리프 등 자체 저작물)이라는 게 명문화돼 있다 — 이게 6장의 킬러 콘텐츠와 정확히 겹친다.

### 10.3 자본시장법 리스크 (컨버전스/시장 기능)

2024년 개정 자본시장법 기준, 양방향 유료 조언(질문답변·개별조언)은 투자자문업 등록 대상, 단방향(뉴스레터·알림)은 유사투자자문업 신고 대상이다. 현재 설계는 DB 스키마에 "추천" 컬럼 자체를 만들지 않고 사실/통계만 저장하는 방식으로 이 리스크를 회피하고 있다. **커뮤니티·Q&A·오픈채팅 기능을 붙이는 순간 양방향이 된다는 경고가 문서에 명시**돼 있어, 향후 기능 추가 시 반드시 재검토 대상이다.

## 12. 정리 — 지금 우선순위 (요청하신 "고쳐주셈"에 대한 답)

여러 세션에 걸쳐 결정은 났지만 실행이 안 끝난 항목들을 모으면, 실제로 손대야 할 일은 생각보다 적고 명확하다.

### 12.1 지금 바로 할 수 있는 것 (코드 작업, 방향은 이미 정해짐)

1. **정보구조(IA) 재배치**: 2장에서 확정된 "개인용 인텔리전스 터미널" 프레임에 맞춰, 3.4절 콘텐츠 매핑 표대로 지정학/지경학 각 모드의 1차 화면·2차 메뉴·제거 대상을 실제로 재배치한다. 이게 UX 감사 3번 항목(제품 정체성)의 유일한 다음 단계다.
2. **레이어 적용 모델 통일**(7.2): draft-확인 모델을 버리고 즉시반영+Undo 토스트로 통일 — 결정은 났고 코드만 안 됐다.
3. **EvidenceTier·출처 카탈로그를 입구 화면에 노출**: 8.3의 양피지 초안을 실제로 구현한다. 이미 콘텐츠는 다 써 있다. WarWatch의 "3단계 검증" 서사에 맞설 유일한 재료가 지금 아무도 안 보이는 곳에 있다는 게 SWOT의 핵심 지적이다.
4. **가짜 데이터 3종 정리**: UCDP GED, 인터넷 교환점(IXP), 제재 대상 명단 — 전부 실행 스크립트는 이미 있고 안 돌린 상태다(`npm run data:ucdp` 등). 정직성 원칙(8.2)에 맞춰 우선순위 높게 처리하거나, 최소한 UI에 "데모 데이터" 표기를 명확히 한다.
5. **면책 고지 형태 변경**(전면 모달 → 상시 하단바)은 법무 확인 3개 문항만 남아 있다 — 법률 자문 후 바로 실행 가능.

### 12.2 방향 결정이 남은 것 (사용자 판단 필요)

1. **ExplorationTabs 처리**: README는 "숨김"이라는데 코드는 양 모드 모두 마운트 — 숨김을 끝낼지 문서를 코드에 맞출지 결정 필요.
2. **하이브리드 관계선의 지정학/지경학 배분**은 렌즈 분리로 일부 정리됐으나 UI 잔여 작업(범례·레일)이 남아 있다.
3. **가격 정책**: TradingView Pro 참고선은 잡혔으나 구체적 가격대·티어 구성은 미정.

### 12.3 지금 당장 손대면 안 되는 것 (섣불리 넓히면 오히려 손해)

### 12.4 가장 중요한 한 문장

**폭(레이어 개수)으로는 이제 이길 수 없다.** Osiris·WarWatch가 이미 넓다. 남은 차별점은 CRINK 축관계망·전략 코리도·지경학 세 가지이고, 공교롭게도 이 셋이 지금 제품에서 가장 미완성인 부분이다. "이것저것 다 넣는" 확장이 아니라 **이 세 가지를 실측·신뢰도·UI 노출 세 방향에서 깊게 파는 것**이 다음 단계 전부여야 한다는 게, 흩어진 문서들을 모아봤을 때 가장 일관되게 반복되는 결론이다.
